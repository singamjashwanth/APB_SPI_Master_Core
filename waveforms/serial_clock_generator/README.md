## Waveform Explanation

### Reset Phase

Initially `PRESET_n` is held low, resetting all internal counters and output signals.

After reset is released (`PRESET_n = 1`), the Serial Clock Generator becomes operational.

---

### Baud Rate Configuration

The testbench applies:

```text
SPPR = 0
SPR  = 2
```

The baud-rate divisor generated by the module is:

```text
BaudRateDivisor_o = 4
```

This divisor controls the frequency of the generated SPI clock.

---

### Slave Select Activation

When:

```text
ss_i = 0
```

SPI communication is enabled and clock generation begins.

As long as Slave Select remains active, the module continues generating SPI timing signals.

---

### SPI Clock Generation

The generated serial clock appears on:

```text
sclk_o
```

When `CPOL = 1`, the clock idles high.

The waveform shows the SPI clock toggling according to the calculated baud-rate divisor.

---

### Receive Clock Pulses

The module generates:

```text
miso_receive_sclk_o
miso_receive_sclk0_o
```

These pulses indicate the clock edges used by the SPI Shifter to sample incoming MISO data.

Only one of these signals becomes active depending on the selected SPI mode.

---

### Transmit Clock Pulses

The module also generates:

```text
mosi_send_sclk_o
mosi_send_sclk0_o
```

These pulses indicate the clock edges used by the SPI Shifter to launch MOSI data.

These timing pulses ensure proper synchronization between transmission and reception.

---

### CPOL Transition

At approximately 650 ps, the testbench changes:

```text
CPOL = 1 → 0
```

As a result:

- Clock idle polarity changes
- Receive timing pulses shift accordingly
- Transmit timing pulses shift accordingly

The waveform demonstrates correct clock generation for both clock polarity settings.

---

### SPISWAI Operation

At the end of simulation:

```text
SPISWAI = 1
```

This requests the SPI clock logic to enter the wait state.

Clock activity stops as expected.
