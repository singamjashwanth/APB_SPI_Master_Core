# SPI Slave Control

## Overview

The **SPI Slave Control** module is responsible for managing SPI transaction flow by controlling the **Slave Select (SS)** signal and monitoring transfer activity. It automatically enables the SPI slave during data transmission, tracks the transfer duration, and generates a receive-complete indication when the transaction finishes.

This module serves as the control logic between the APB interface and the SPI data path, ensuring proper synchronization of SPI transfers.

## Key Features

- Automatic Slave Select (SS) control
- Transfer duration management using baud rate settings
- Transfer-In-Progress (TIP) indication
- Receive-complete pulse generation
- Master mode operation support
- Wait mode and stop mode handling
- Active-low asynchronous reset
- Fully synchronous implementation

---

## Functional Description

### Slave Select Generation

Whenever a new transmission request is received through `send_data_i`:

- `ss_o` is asserted LOW
- Internal transfer counter starts
- The slave remains selected until the transfer completes

This guarantees that the SPI slave stays active throughout the entire transaction.

---

### Transfer Duration Control

The transfer duration is determined using the baud-rate divisor generated by the Serial Clock Generator.

The target transfer count is calculated as:

```verilog
assign target_s = BaudRateDivisor_i * 16;
```

The controller keeps the transaction active until the internal counter reaches this target value.

---

### Receive Complete Indication

Near the end of the transfer:

- Internal flag `rcv_s` is asserted
- On the following clock cycle, `receive_data_o` is generated
- The APB interface uses this pulse to capture received MISO data

This mechanism ensures that received data is sampled only after the SPI transaction has fully completed.

---

### Transfer Completion

After the transfer duration expires:

- `ss_o` is deasserted HIGH
- Transfer counter resets
- Receive flag clears
- Module returns to idle state

## Transfer-In-Progress Logic

The TIP signal is derived directly from the Slave Select output:

```verilog
assign tip_o = ~ss_o;
```

### TIP Status

| SS | TIP |
|----|-----|
| 1 | 0 |
| 0 | 1 |

When the slave is selected (`SS = 0`), the transfer is considered active.

---

## SPI Operating Modes

Transfers are permitted only under valid SPI operating conditions.

### Run Mode

```text
spi_mode_i = 2'b00
```

SPI transfers are enabled.

---

### Wait Mode

```text
spi_mode_i = 2'b01
spiswai_i = 0
```

SPI transfers continue normally.

---

### Stop Mode

Transfers are disabled when:

```text
spi_mode_i = 2'b01
spiswai_i = 1
```

or

```text
spi_mode_i = 2'b10
```

Under these conditions:

```text
SS  = 1
TIP = 0
```

No SPI transaction is allowed.

---

## Transfer Flow

```text
send_data_i asserted
        │
        ▼
Slave Select asserted LOW
        │
        ▼
Counter starts running
        │
        ▼
SPI transfer active
        │
        ▼
Counter reaches target value
        │
        ▼
Receive-complete pulse generated
        │
        ▼
Slave Select released HIGH
        │
        ▼
Transfer finished
```
